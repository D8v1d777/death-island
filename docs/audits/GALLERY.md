# Current gameplay gallery

The six README images are 1280x720 Godot 4.3 Compatibility viewport captures.
The runner first captures the main title/character-select menu, then starts Dave
through the production new-game API, arranges bounded inventory/encounter fixtures,
and calls real movement, interaction, combat, cooking and building APIs.
Images are never composited or presented as target-phone photographs.

## Regeneration

```bash
python3 tools/check.py
DEATH_ISLAND_GALLERY_DIR="$PWD/docs/images" python3 tools/check.py --gallery
python3 tools/validate_gallery.py docs/images --readme README.md
```

Without the environment override, `--gallery` writes to `build/gallery/`, suitable
for CI. It uses Xvfb/OpenGL, seed 20261030 and fixed simulation FPS 30. The fixed
simulation FPS is not a measured rendering-performance claim. GPU/driver/font
differences may change encoded bytes; state/scenario results must remain valid.

The wrapper rejects engine errors, requires six successful actions, checks WebP
containers, source/engine metadata and SHA-256 digests, and runs Godot's decoder
against all six files. Decoded images must be nonblank, distinct and 1280x720.
`gallery.json` records source revision (the source commit before capture/artifact
commit), character/texture, scenario, menu, frame, dimensions and actual state changes.

## Scenarios

| File under `docs/images/` | Expected evidence |
|---|---|
| `01-title-character-select.webp` | Main menu and Dave/Marie title-screen character selection |
| `02-dave-explore-wreckshore.webp` | Movement >0.3m; Dave, wreck, beacon, shoreline and mobile HUD |
| `03-dave-gather-companion.webp` | Wood count increases; axe pose, resource node and reward feedback |
| `04-combat-companion-assist.webp` | Enemy health decreases; attack pose, boar, damage feedback and HUD |
| `05-campfire-cooking.webp` | Cooked meat present after cooking; campfire and survival HUD |
| `06-shelter-building.webp` | Four successful placed parts; completed shelter and camp environment |

The six files are generated by the live gameplay runner and validated by the
manifest, SHA-256 checks, WebP container checks and Godot image decoder. A successful
capture run does not certify phone rendering, performance or production art quality.

Visual acceptance covers readable gameplay captures and correct current interim
texture use. It does not approve reference fidelity, full animation sets, phone
performance or production art.
